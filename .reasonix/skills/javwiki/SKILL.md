# JAV 百科维护

在仓库根目录执行操作。先读取目标文件及相邻条目，沿用现有格式；不要凭模板覆盖条目中更丰富的字段。

## 内容原则

- 把可核实事实与概括性描述分开；不把搜索摘要、粉丝站或 AI 生成文本当作事实来源。
- 对出生日期、三围、所属事务所、活动状态等易冲突或易变化信息进行交叉验证，并保留直接来源链接。
- 不确定的信息写明来源差异或暂不写入，禁止猜测。
- 使用简体中文叙述；艺名、厂牌、奖项等专名保留可靠来源中的正式写法。
- 避免“顶流”“最具代表性”“深受喜爱”等无来源宣传语。
- 外部资料与社交账号可能变化。用户要求查新、核实或补资料时先联网验证。

## 联网获取资料

优先按以下顺序获取可靠资料：

1. **Wikipedia**（ja / zh / en）—— WebFetch 工具可能因缺少 User-Agent 被拒返回 403，不代表页面不存在。改用 curl 验证与抓取：

   ```bash
   # 检查页面是否存在
   curl -sI -H "User-Agent: Mozilla/5.0" "https://ja.wikipedia.org/wiki/女优名"

   # 抓取正文内容
   curl -s -H "User-Agent: Mozilla/5.0" \
     "https://ja.wikipedia.org/w/api.php?format=json&action=parse&page=女优名&prop=text"
   ```

2. **FANZA / DMM**—— 无需登录即可获取作品基本信息（品番、标题、发行日、出演者）。需通过年龄确认页后抓取。

3. **JavDB**—— 提供品番搜索、演员页、评分与标签。资料丰富但属二次聚合站，关键事实（出生日期、三围等）须以 Wiki 或官方来源交叉验证。

4. **jav.guru** 等聚合站—— 参考作品标题与标签，不作为人物基本信息的唯一来源。不采信其中的年龄、身高、三围等未经原文引用的字段。

验证身份时，**作品标题**是重要线索：标题中的人设（如「神戸の人妻」）可能是制作方为作品设定的人物背景，**不代表演员的真实个人信息**（如实际出生地）。遇到此类信息须以 Wikipedia 或经纪公司官方资料为准。

5. **Yahoo.co.jp 检索**——见下节独立步骤（官方档案、本人博客、作品收录页、事务所 RELEASE、活动预告、引退/改名报道）。

## 资料可靠性分级

- **本人一手**（事务所档案、本人博客/SNS）：可直接写入，内联注明来源。
- **权威二次**（有出处的 wiki、Filmarks/FOD/U-NEXT 收录页）：可写入，附参考链接。
- **粉丝整理**（引退まとめ等）：仅用于补年表/旧艺名，必须标注"据 XX 整理"，不作唯一来源。
- **匿名问答与评论**（知惠袋、livedoor 评论）：不写入正文，仅作线索或参考链接；整形/丰胸/年龄造假类猜测一律不收录。
- 同名异人必须排除（如 ameblo 上的同名普通博客）；社交账号换代（旧号/应援号）须验证后再写入。

## Yahoo 检索与抓取（独立步骤）

当前 `web_search` 在本机常年不可用（DuckDuckGo 机器人墙、各浏览器 daemon 起不来），Yahoo.co.jp 直读是实际可用的搜集入口，单列一步，前 4 项走完仍缺关键事实（事务所档案、SNS 现号、引退/改名、FANZA 演员 ID）时执行。

### 搜索

- 入口：`https://search.yahoo.co.jp/search?p={quote(查询)}&ei=UTF-8`，翻页加 `&b=N`（11/21/31…）。
- 结果页可用 `read` 直接读（canonical + 10 条摘要含真实目标 URL）。
- 过滤站内导航链：`search.yahoo.co.jp`、`r.ms.yahoo`、`login.yahoo`。
- 查询词至少覆盖：本名/艺名、改名后名字、`所属事务所名`、所属团体（如 OFA21）、`ブログ`、`知恵袋`、年份+片商（如 `2025 Madonna`）。
- 每轮取前 10 条，只跟进与目标同名且可交叉的页（事务所/片商/本人 SNS/U-NEXT/FANZA/杂志访谈）；聚合站、2ch まとめ只记线索不直接采用。

### 抓取

- 目标页优先用 `read` 直读：事务所官方档案（含 SIZE/生日/官方链接/RELEASE 新作）、本人博客（楽天/ameblo/livedoor）、FOD/U-NEXT/Filmarks 出演一览、FANZA 演员页（记 `actress=` ID）、Wayback 存档。
- 浏览器 daemon 不可用时，用 Python Playwright（headless + ja-JP locale + 桌面 UA）：`domcontentloaded + 2~3s` 后取 `innerText` 前 4–6k 字。
- 抓到即记可靠性分级（本人一手 / 权威二次 / 粉丝整理 / 匿名问答），分级决定能否入正文。

### 知恵袋（固定子步骤）

Yahoo 搜索轮次中必须带一轮 `知恵袋` 查询（`女优名 + 知恵袋` / `改名前 + 引退` / `改名前 + 事务所`），不直接采信回答，只做两件事：

- **找线索**：旧艺名/改名链、引退时期、事务所归属、作品品番提示——拿到后必须用一手或权威二次交叉，交叉不上只记“待证实”不入正文。
- **辨分歧**：生日/身高/罩杯出现多口径时（如椎名空 1994-07-07 vs 1995-07-12），知惠袋问答可佐证“分歧存在”，但不能裁决，裁决只认事务所/片商/本人。

硬规则：匿名回答永不作唯一来源；整形/丰胸/年龄造假/引退原因猜测一律不收录；引用时注“据知惠袋问答（待交叉）”。

### 结果处理

- 事务所档案与 Wiki 口径冲突（生日/三围/罩杯/出身）→ 正文双源并列，不猜。
- SNS 换代（旧号/应援号）→ 以事务所页 + 本人页互证为准，旧号注记不用作主链接。
- 引退/改名/专属起止 → 要本人或事务所/片商一手出处；粉丝站转引必须注“据 XX 转引/整理”。

## 新增或编辑女优

1. 读取 `src/_meta/五十音排序规则.md`，按艺名读音的首假名确定 `src/{行}/{段}/{女优名}.md`。
2. 查看同段 2–3 个条目，复用当前 frontmatter、标题与章节风格。
3. 至少维护以下内容：
   - frontmatter：`tags`；只有图片已核验时才加 `thumbnail`。
   - `# 女优名`
   - `## 基本信息`
   - `## 简介`
   - `## 经历年表`
   - `## 参考资料`
4. 仅在有可靠资料时增加人物、作品特征、获奖记录、社交媒体等章节。
5. 新增条目时，把链接插入 `src/{行}/{段}/index.md` 的“条目”列表。行索引只维护段链接，通常无需加入单个女优。
6. 检查文件名、H1、姓名字段、图片 alt 文本和索引显示名是否一致。

基本信息建议顺序：

```markdown
- **姓名**:
- **日文名**:
- **读音**:
- **英文名**:
- **出生日期**:
- **出生地**:
- **身高**:
- **三围**:
- **罩杯**:
- **类别**:
- **活跃年代**:
- **经纪公司**:
- **主要片商**:
```

省略无法证实的字段，不填“未知”占位。经历年表按时间升序，使用同一张表中的统一粒度。

## 图片

添加或修复女优图片时，必须读取并遵循相邻技能 `../add-actress-images/SKILL.md`。确保 `thumbnail` 与正文 `<img src>` 使用同一 URL。

## 其他条目

- 厂牌：`src/厂牌/{名称}.md`
- 经纪公司：`src/经纪公司/{名称}.md`
- 元资料及来源：先检查 `src/_meta/`
- FANZA 月榜采集：先读 `scrapers/fanza/README.md`，输出到 `src/_meta/rankings/`
新增任何页面后确认其可由相应索引或自动生成的 `SUMMARY.md` 到达。不要手工维护生成目录 `book/`、`_tags/` 或根目录 `SUMMARY.md`。

## 验证

先检查改动范围：

```bash
git diff --check
git diff --stat
git diff -- src/
```

范围型编辑后重读改动区首尾：确认无吞行、无重复行，表格表头与章节标题完好。

内容改动至少确认内部相对链接存在。工具齐全时执行与 CI 相同的流程：

```bash
mdbook-tagging generate .
mdbook-summarizer --src src --auto-readme
mdbook build
```

若缺少某个工具，运行可用的检查并明确报告未执行项；不要为一次内容编辑擅自全局安装工具。生成文件只在项目既有策略要求时提交。

## 发布

只有用户明确要求发布或推送时才提交并推送。遵循仓库级 `AGENTS.md`；本项目发布到 `main` 后由 `.github/workflows/mdbook.yml` 部署。
