# JAV 百科维护

在仓库根目录执行操作。先读取目标文件及相邻条目，沿用现有格式；不要凭模板覆盖条目中更丰富的字段。

## 内容原则

- 把可核实事实与概括性描述分开；不把搜索摘要、粉丝站或 AI 生成文本当作事实来源。
- 对出生日期、三围、所属事务所、活动状态等易冲突或易变化信息进行交叉验证，并保留直接来源链接。
- 不确定的信息写明来源差异或暂不写入，禁止猜测。
- 使用简体中文叙述；艺名、厂牌、奖项等专名保留可靠来源中的正式写法。
- 避免“顶流”“最具代表性”“深受喜爱”等无来源宣传语。
- 外部资料与社交账号可能变化。用户要求查新、核实或补资料时先联网验证。

## 联网获取资料

优先按以下顺序获取可靠资料：

1. **Wikipedia**（ja / zh / en）—— WebFetch 工具可能因缺少 User-Agent 被拒返回 403，不代表页面不存在。改用 curl 验证与抓取：

   ```bash
   # 检查页面是否存在
   curl -sI -H "User-Agent: Mozilla/5.0" "https://ja.wikipedia.org/wiki/女优名"

   # 抓取正文内容
   curl -s -H "User-Agent: Mozilla/5.0" \
     "https://ja.wikipedia.org/w/api.php?format=json&action=parse&page=女优名&prop=text"
   ```

2. **FANZA / DMM**—— 无需登录即可获取作品基本信息（品番、标题、发行日、出演者）。需通过年龄确认页后抓取。

3. **JavDB**—— 提供品番搜索、演员页、评分与标签。资料丰富但属二次聚合站，关键事实（出生日期、三围等）须以 Wiki 或官方来源交叉验证。

4. **jav.guru** 等聚合站—— 参考作品标题与标签，不作为人物基本信息的唯一来源。不采信其中的年龄、身高、三围等未经原文引用的字段。

验证身份时，**作品标题**是重要线索：标题中的人设（如「神戸の人妻」）可能是制作方为作品设定的人物背景，**不代表演员的真实个人信息**（如实际出生地）。遇到此类信息须以 Wikipedia 或经纪公司官方资料为准。

## 新增或编辑女优

1. 读取 `src/_meta/五十音排序规则.md`，按艺名读音的首假名确定 `src/{行}/{段}/{女优名}.md`。
2. 查看同段 2–3 个条目，复用当前 frontmatter、标题与章节风格。
3. 至少维护以下内容：
   - frontmatter：`tags`；只有图片已核验时才加 `thumbnail`。
   - `# 女优名`
   - `## 基本信息`
   - `## 简介`
   - `## 经历年表`
   - `## 参考资料`
4. 仅在有可靠资料时增加人物、作品特征、获奖记录、社交媒体等章节。
5. 新增条目时，把链接插入 `src/{行}/{段}/index.md` 的“条目”列表。行索引只维护段链接，通常无需加入单个女优。
6. 检查文件名、H1、姓名字段、图片 alt 文本和索引显示名是否一致。

基本信息建议顺序：

```markdown
- **姓名**:
- **日文名**:
- **读音**:
- **英文名**:
- **出生日期**:
- **出生地**:
- **身高**:
- **三围**:
- **罩杯**:
- **类别**:
- **活跃年代**:
- **经纪公司**:
- **主要片商**:
```

省略无法证实的字段，不填“未知”占位。经历年表按时间升序，使用同一张表中的统一粒度。

## 图片

添加或修复女优图片时，必须读取并遵循相邻技能 `../add-actress-images/SKILL.md`。确保 `thumbnail` 与正文 `<img src>` 使用同一 URL。

## 其他条目

- 厂牌：`src/厂牌/{名称}.md`
- 经纪公司：`src/经纪公司/{名称}.md`
- 元资料及来源：先检查 `src/_meta/`
- FANZA 月榜采集：先读 `scrapers/fanza/README.md`，输出到 `src/_meta/rankings/`

新增任何页面后确认其可由相应索引或自动生成的 `SUMMARY.md` 到达。不要手工维护生成目录 `book/`、`_tags/` 或根目录 `SUMMARY.md`。

## 验证

先检查改动范围：

```bash
git diff --check
git diff --stat
git diff -- src/
```

内容改动至少确认内部相对链接存在。工具齐全时执行与 CI 相同的流程：

```bash
mdbook-tagging generate .
mdbook-summarizer --src src --auto-readme
mdbook build
```

若缺少某个工具，运行可用的检查并明确报告未执行项；不要为一次内容编辑擅自全局安装工具。生成文件只在项目既有策略要求时提交。

## 发布

只有用户明确要求发布或推送时才提交并推送。遵循仓库级 `AGENTS.md`；本项目发布到 `main` 后由 `.github/workflows/mdbook.yml` 部署。
