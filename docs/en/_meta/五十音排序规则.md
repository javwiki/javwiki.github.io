# Gojūon sorting rules

This document defines how the encyclopedia's actress directory system and `list.yaml` are ordered, so that the entry index, the file system and the list file stay consistent with one another.

## Rows and columns of the gojūon

The directory structure uses a **two-level index over the gojūon chart**:

| Row (行) | Column (段) |
|----------|----------|
| あ行 | あ・い・う・え・お |
| か行 | か・き・く・け・こ |
| さ行 | さ・し・す・せ・そ |
| た行 | た・ち・つ・て・と |
| な行 | な・に・ぬ・ね・の |
| は行 | は・ひ・ふ・へ・ほ (including voiced ば・び・ぶ・べ・ぼ and semi-voiced ぱ・ぴ・ぷ・ぺ・ぽ) |
| ま行 | ま・み・む・め・も |
| や行 | や・ゆ・よ |
| ら行 | ら・り・る・れ・ろ |
| わ行 | わ・を・ん |

Voiced and semi-voiced kana join their base row:
- **ば行** belongs to **は行** (べ → row は, column べ)
- **ぱ行** belongs to **は行**

## How an actress's position is decided

Each actress's row and column follow the **reading of her stage name**:

### Kanji names

Read the kanji in on'yomi to get the kana, then take the **first kana** to fix the position.

Examples:
- 河北彩花 (かわきた さいか) → first kana 「か」 → row か, column か
- 相泽南 (あいざわ みなみ) → first kana 「あ」 → row あ, column あ
- 深田咏美 (ふかだ えみ) → first kana 「ふ」 → row は, column ふ

### Katakana / loanword names

Take the actual pronunciation of the katakana and use its **first kana**.

Examples:
- ベアトリクス (べあとりくす) → first kana 「べ」 → row は, column べ
- アイカ (あいか) → first kana 「あ」 → row あ, column あ
- ミル (みる) → first kana 「み」 → row ま, column み

### Mixed names

Kanji plus kana: still judge by the first kana of the reading as a whole.

Examples:
- あずみ恋 (あずみ れん) → first kana 「あ」 → row あ, column あ

### Voiced / semi-voiced kana

Voiced and semi-voiced kana are grouped by their own kana (ば and ぱ belong to the は row).

- A reading starting with 「ば・び・ぶ・べ・ぼ」 → row は plus the matching column
- A reading starting with 「ぱ・ぴ・ぷ・ぺ・ぽ」 → row は plus the matching column

## list.yaml structure

```yaml
title: 女优列表
items:
  - name: 女优名      # 艺名（汉字/片假名/英文）
    row: 行           # 五十音行名（あ/か/さ/...）
    col: 段           # 五十音段名（あ/い/う/...）
    completeness: N%  # 条目完整度（0-100）
```

### Sorting rules

items are ordered as follows:
1. **Row order**: あ → か → さ → た → な → は → ま → や → ら → わ
2. **Column order**: あ → い → う → え → お

Actresses then fall in sequence inside this grid according to their readings.

## File-system mapping

Directory path: `docs/{row}/{col}/{name}.md`

Examples:
- `docs/か/か/河北彩花.md`
- `docs/は/べ/ベアトリクス.md`
- `docs/ま/み/Miru.md`

Each `{row}/` directory must hold an `index.md` (row index), and each `{row}/{col}/` directory must also hold an `index.md` (column index).

## Consistency constraints

These three must correspond exactly:
1. The `row` / `col` values in **list.yaml**
2. The directory paths in the **file system**, `docs/{row}/{col}/`
3. The entry links in the **directory indexes** `docs/{row}/index.md` and `docs/{row}/{col}/index.md`

Any addition, change or deletion must update all three places at once.

## Completeness

| Level | Meaning |
|------|------|
| 100% | The entry is complete (profile, introduction, work features, timeline and references all present) |
| 65%  | The entry has its basic structure, but some sections are missing |
| 10%  | Skeleton only; content still to be filled |
| 0%   | Not yet created |
