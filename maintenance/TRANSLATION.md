# 中日英文内容 i18n 迁移说明

本文记录 2026-09-20 将本站由单一中文内容树迁移为中文、日文和英文三语内容站点时使用的目录结构、翻译方式、结构契约、实测规模、验证结果和后续维护约定。

中文（`docs/zh/`）是唯一源内容。英文初版为机器翻译初稿，2026-09-24 已依据中文源逐篇重写（见「英文：依据中文源重写」）；日文初版机翻不可用，已依据中文源重建，但同样不代表逐篇重新调查、重新编写或人工校订。任何一版都未替代事实核验。

## 当前目录约定（2026-10-09）

本次迁移已将人物、作品、产业和资料分层，女优路径统一为 `docs/{lang}/人物/女优/{行}/{段}/`。纯维护资料在 `maintenance/{lang}/`，脚本分为 `scripts/checks/`、`scripts/content/` 和 `scripts/i18n/`。当前操作方法和元数据约定以 [维护指南](README.md) 与 [脚本文档](../scripts/README.md) 为准；下文保留之前各轮迁移的规模与执行记录。新增或移动页面后运行索引／导航生成器，再执行三语严格构建。

## 内容树结构

三个语言目录使用**完全相同的相对路径**，例如：

```text
docs/zh/资料/法律/民法.md
docs/ja/资料/法律/民法.md
docs/en/资料/法律/民法.md
```

文件名和目录名一律不翻译。这使三棵树可以直接逐文件比对，也避免语言切换时维护额外的路径映射。代价是中文目录名（如 `../女优/index.md`）会出现在日文和英文页面的链接里。

### 五十音索引

女优条目按「行 / 段」两级存放：`docs/{行}/{段}/{艺名}.md`。行分 あ・か・さ・た・な・は・ま・や・ら・わ 共 10 行，段为各行内的 あ・い・う・え・お 等。条目归入哪个段由**艺名读音的首个假名**决定，浊音与半浊音并入所属行（が行归 か行，ば・ぱ 行归 は行）。

- 行索引 `docs/{行}/index.md` 只链接各段。
- 段索引 `docs/{行}/{段}/index.md` 列出该段全部条目。
- 行、段目录名本身就是假名，条目文件名则是艺名的中文写法。

排序与定位规则的完整说明见 `maintenance/{lang}/五十音排序规则.md`。

**当前相对链接层级**：女优页面位于 `人物/女优/{行}/{段}/`。同一女优分类内跨行仍用 `../../`，跨到语言根目录下的产业或作品分类用 `../../../../`。

```text
docs/zh/人物/女优/は/は/桥本有菜.md → ../../あ/あ/新有菜.md
docs/zh/人物/女优/や/よ/米倉穂香.md → ../../../../作品/单部/KBI-001.md
docs/zh/产业/制作公司/Prestige.md → ../../人物/女优/な/な/七泽美亚.md
```

所有实际 Markdown 链接由 `check_i18n.py` 检查目标文件，生成页面链接与锚点由 `check_site.py` 检查。目录名和文件名三语一致，链接显示文字按语言翻译。

## 英文：依据中文源重写（2026-09-24）

上述 OPUS-MT 初稿的专名与语义错误过多（H1、人名、机构名大面积误译），2026-09-24 起依据 `docs/zh/` 逐篇重写，覆盖全部 357 个文件的正文（女优条目 181 篇、分类条目与索引、`_meta` 与专题）。结构契约与受保护区规则不变：front matter（除 `title`）、`<img>` 行（仅 `alt` 本地化）、链接目标、标题层级、表格形状、代码围栏、受保护区逐字保留。重写后仍未经人工校订。

### 英文显示名

- 人名以中文源的 `英文名` 字段为准（172 条）；字段缺失的 9 条按源内读音回填，override 写在脚本里。显示名应用于 H1、图片 `alt`、指向女优条目的链接显示文字、`_meta/list.{md,yaml}`。
- **正文首次提及同样用显示名**：`## Introduction`、`## Personal notes` 的段首与列表项若以中文文件名形式（`苍井空 is one of …`）开头，改为该页 H1 的显示名（`Sola Aoi is one of …`），与日文版以日文标准名开头一致。`scripts/i18n/en_fix_name_openings.py` 负责这一替换，幂等。
- 显示名只替换**主语位**。作品名、官方标题、`「」` 内的艺名、Wikipedia 等 URL、`**Name**` 与 `**Japanese name**` 字段值一律保留原写法。
- 官方原文保留原文、不做罗马字化：厂商名、系列名、法律名、中文源中已是官方日文写法的人名、数据单元格中的出演者/得主名；中文源只有中文译名且无读音的人名保留源写法。**例外**：中文源已给出官方外文名的专名（如 `惠比寿★麝香葡萄` 的 `英文名: Ebisu Muscats`）在英文正文中一律用该外文名，不使用中文音译写法。
- 行/段索引标题英文在前、日文括注：`# A row (あ行)`、`# A column (あ段) — A row (あ行)`；`_meta/list.md` 同口径；表头行/段译作 Row/Column。
- 术语表的括注用**日文原词**（`Studio (メーカー)`、`Agency (事務所)`、`Label (レーベル)`、`Prefix (プレフィックス)`、`Sequence number (シリアル番号)`），不用中文词；括注外的说明文字仍为英文。

## 日文：依据中文源重建

日文初版由「中文 → 英文 → 日文」二级机器翻译生成（OPUS-MT `translate-en_ja` 1.1，约 37 分钟）。该路径把英文初稿的误差再放大一次，产出不可用：

- **专有名词被意译或音译**：`蒼井そら` → `葵くん`，`相沢みなみ` → `アゼンアム`，`日文名` 字段值 → `彩公社事務所`；
- **中文源中保留的官方日文原文被英文回译摧毁**：`IPX-177` 的日文原文变成 `ヒエナ、ハイエナ、ハイエナ…`，作品名变成「地域は「甘み」と「甘み」の長い歴史を国に持ちます。」；
- **结构被当作正文翻译**：`_meta/list.yaml` 的 `items` → `アイテム`，排名 YAML 的 `rankings`/`rank` → `ランキング`/`ランク`，人名 → `申し訳ございません。`；
- **重复退化**：`全て正しいです。 アパート`、`年 年 年 年`，以及 `とりあえず` 之类的插入语。

因此日文版改为**依据中文源逐文件重新改写**，不再使用「中文 → 英文 → 日文」产物——中文源里本就保留着官方日文专名（`強制中出し 射精執行官`、`スカパー!アダルト放送大賞`、`AV出演被害防止・救済法`、`恵比寿★マスカッツ` 等），从中文源出发才能拿回这些写法。重写按目录切成 28 个分片并行执行，每个文件都先取 `docs/zh/` 对应页面的事实，再写成日语，不新增、不删减任何事实、数字、日期或链接。

### 演员名对照

演员名在三棵树里指向同一文件名，但显示写法不同。日文标准名来自两个固定来源：

1. 各条目的 `日文名` 字段（中文源自身持有）；
2. `maintenance/ja_name_map.json`——迁移前批量抓取时使用的艺名映射表。

两者合成一张固定的「中文文件名 → 日文标准名」对照表（180 条），日文页面的 H1、`名前` 字段、链接显示文字、正文与表格统一使用该写法。例如 `相泽南`→`相沢みなみ`、`苍井空`→`蒼井そら`、`三上悠亚`→`三上悠亜`、`朝美穗香`→`みひろ`。表格中带空格的写法（如 `篠田 ゆう`、`澁谷 果歩`）沿用中文源 `日文名` 字段的原样。

**日文版把 `姓名` 与 `日文名` 合并为一个 `名前` 字段**（174 个女优页）：中文源的两行分别是中文艺名与官方日文名，日文版只保留官方日文名一行，行数因此比中文源少 1。`check_i18n.py` 不比较列表项行数，故这项差异需靠本文件记录；除该字段外，三语页面的正文行、列表项与表格行逐行对应。

### 确定性重建的部分

以下文件不适合逐篇改写，直接由中文源以脚本重建：

- `docs/ja/{行}/{段}/index.md` 等 47 个五十音索引页：条目链接的**显示名**换成日文标准名，**链接目标**保持中文源原样；表头改为 `## 記事一覧`、`## 段インデックス`。
- `maintenance/ja/list.{md,yaml}`：条目名换为日文标准名，`title` 改为日文，其余键名与结构不变。
- `docs/ja/资料/排名/actress-ranking-*.yaml`：与中文源逐字节一致——这是数据文件，键名本就是英文，人名使用 FANZA 官方写法。
- front matter 的 `title:`：决定页面标题与导航显示名，改为日文并与各自 H1 一致（6 个页面涉及奖项、活动、专题）。

## 结构契约

日文重建与英文机翻都遵守同一套结构契约，可概括为「**结构冻结，正文翻译**」。

保持与中文源一致：

- YAML front matter（唯一例外见下）；
- 链接目标、裸 URL、图片 `src`、文件路径；
- 标题层级序列（数量、层级、顺序），标题文字翻译；
- 表格的行列数与分隔行，单元格文字翻译；
- 代码块数量与围栏语言标记，块内内容不翻译；
- HTML 标签及其属性（`alt` 除外，`alt` 改为该页主题在当语版本中的写法）。

会翻译的内容：标题、段落、列表正文、表格单元格、链接显示文字、`alt` 属性。

### 允许的差异

- **front matter 的 `title:`**：页面与导航的显示标题，按语言翻译。其余字段（`tags`、`thumbnail`、`type`、`number` 等）保持中文源原值，包括 `tags` 里仍是中文的词（`企画单体`、`跨性别`、`E杯`）。
- **作品页的引用小节（受保护区）**：`### 日文原文（missAV / FANZA）` 一节保存的是官方日文文案，三棵树逐字相同，因此在日文版中保留中文小节名不改；`### 中文翻译` 在日文版中改名为 `### 中国語訳`，正文仍为中文，作为对照保留；英文版对应 `### Original Japanese (missAV / FANZA)` 与 `### Chinese translation`。这两节**只能从 `docs/zh/` 原样拷贝，任何语言都不译**，包括其中的 `> 注` 前导说明行——它位于受保护区内，故中文版也保持中文，英文版同样保留中文（英文版的完整重译另行处理）。校验按节比对，忽略小节结尾多余的空行。
- **文件名、目录名与链接目标**：不翻译，因此日文、英文页面中出现中文路径与中文链接目标是预期行为。
- **中文源中只有中文译名的专有名词**：若中文源未给出官方日文写法（部分作品名、电影名、活动名），日文版按中文原文保留或按新字体转写，不臆造标题。

- **专名以字段为准，正文可保留官方原文**：当 front matter 的 `tags` 与正文写法冲突时，以结构化字段（`tags`、`经纪公司`/`所属事務所`）为裁定依据。若两者写法不同而指同一实体，正文首次出现改为「`条目名（官方原文）`」并列的形式，不改文件名。
- **日文版合并 `姓名` 与 `日文名`**：日文页面的基本信息只写 `名前`（日文标准名）一行，比中文源少一行，详见「演员名对照」。这是三语间唯一的行数差异。
- **同一页面内不得混用两种写法**：一版之内同一实体只出现一种写法（`Ebisu Muscats` 或 `恵比寿★マスカッツ`，不混用；中文源给出 `英文名` 时英文版用外文名）。

### 事务所 tag 命名规范

2026-09 内容修复后，三语 `tags` 逐字节一致，并遵循以下口径（**刻意不做整体日化或英化**——那会破坏「官方写法」与「条目名」的绑定）：

1. **同一家公司只用一个 tag。** 不留 `前X` 与 `X` 双挂，也不留写法变体（如 `オールプロモーション` / `Allpro` 并存）。
2. **有经纪公司条目页的，tag 用条目名**（拉丁字母写法）：`Allpro`（= オールプロモーション）、`Prime Agency`（= プライムエージェンシー）、`8MAN`、`Diaz Group`、`ロータスグループ`、`Madonna`、`Prestige` 等。
3. **无条目页的，tag 用公司官方原文**，日文原文照抄（`カプセルエージェンシー`、`リスタープロ`、`名東`、`ジュンプロ`、`ジールグループ`、`アトラクティブ`）。
4. **「曾所属」写进正文的 `经纪公司`/`所属事務所` 字段**，不体现在 tag 里：写 `リスタープロ（2025年至今）、Allpro（オールプロモーション，前，2015-2019）`，tag 只保留 `Allpro` 与 `リスタープロ` 两项。
5. **改名后用现名**：`SO MODEL AGENT`（旧称 8MAN）统一用 `8MAN`；`オールプロ` / `All Promotion` 统一用 `Allpro`。
6. **条目页与 tag 必须互相印证**：`经纪公司/{公司}.md` 列出的成员，其 `tags` 中应含该 tag；反之正文写明现属该公司的，补上 tag（如 `北川绘里香` 补 `Allpro`）。

改 tag 后须同步三语，并检查正文对应字段是否用同一写法（见上一条「专名以字段为准」）。

## 验证

`scripts/checks/check_i18n.py` 是内容校验的入口，依赖由根目录 `pyproject.toml` 与 `uv.lock` 固定。执行四类检查：

1. **文件集合**：三个语言目录的文件相对路径必须完全一致，多一个或少一个都报错（覆盖全部 358 × 3 个文件）。
2. **结构一致**：逐页比对 `docs/ja/`、`docs/en/` 与 `docs/zh/` 的 Markdown 页面——front matter（除 `title:`）、标题层级序列、按文档顺序排列的链接/自动链接/图片目标、表格形状（每行竖线数）、代码块数量与开启围栏的语言标记。共 710 页。
3. **链接与索引完整性**（按语言独立检查，不与中文源比对）：
   - 链接目的地不得含裸空格——正则若截断成 `Bambi Promotion.md` → `Bambi`，比对两侧反而一致，属于静默盲区；
   - 所有相对链接必须能解析到文件或含 `index.md` 的目录，二级目录页的 `../../` 层级由此兜住；
   - `{行}/{段}/index.md` 必须列出该段全部条目；
   - Markdown 中不得出现脚本、iframe、object、embed、form、事件属性或 `javascript:` 等主动 HTML（代码围栏示例除外）。
4. **数据完整性**：
   - `_meta/list.yaml`、`排名/*.yaml` 必须能解析为 YAML；
   - `list.yaml` 必须有 `title` 与 `items`，每条有非空的 `name`/`row`/`col`/`completeness`，无重名，且三语条数一致；
   - `list.md` 的名称及顺序必须与本语 `list.yaml` 一致；中文源 `row`/`col`/`name` 必须对应真实演员页面，目标语言可翻译显示名，但 `row`/`col`/`completeness` 不得漂移；
   - 中文源 `排名/*.yaml` 必须通过 schema 检查：顶层字段齐全、`count` 与行数相等、排名为连续 `1..N`、演员 ID 不重复、条目必填字段类型正确；
   - `排名/*.yaml` 必须与 `docs/zh/资料/排名/` 逐字节一致；
   - `作品/` 页及 `活动/JAE.md` 的受保护区（日文原文、中文翻译两节）必须与中文源逐字节一致（忽略小节尾部空行数）。

### 跨语言校对（2026-09-28）

`check_i18n.py` 只看结构，看不见「整句丢失」「数字对不上」「专名写法不一致」。为此另做了一轮三语对照校对，方法是把每页正文按「结构类型 + 链接目标」对齐后逐行比对：

| 检查 | 方法 | 结果 |
|---|---|---|
| 内容行缺失 | 按（标题层级/表格行/列表项/段落，链接目标）对齐三语行序，取差集 | 除日文版合并 `姓名`（174 页）外，三语正文行完全对应 |
| 数字与日期漂移 | 归一化后比较数字多重集：日期（`1996年11月30日` / `30 November 1996`）、年月、区间、英文数词、`万/亿` 与 `million/billion` 互换、中文数字词（一百多万 / one million） | 高置信漂移从 1396 降到 117，逐条核对后仅 1 处真实错误 |
| 未翻译残词 | 在英文正文里找中文函数词与动词（`话题`、`推进`、`直播导航`、`事务所` 等） | 12 处，全部修正 |
| 专名一致性 | 中文源有 `英文名` 的专名，在目标语言里查是否仍用中文音译 | `惠比寿麝香葡萄` → `Ebisu Muscats`（69 处） |

已修的真实错误（英文版）：

- 12 处改写残留的重复/错位短语（`in April... in February`、`In 2018... on …`、`A fan of … whose favourite character is ヒバル恭弥... — …` 等）；
- 事实错误 1 处：`葵百合香` 的 FANZA 周榜年份 2024 → 2023（中文源为 2023-05-15 当周）；
- 中文音译的专名 5 处（`ちっぱい女优`→`ちっぱい女優`、`本格的大罩杯`→`本格的な巨乳`、`AV事务所`→`AV事務所`、`令和史上最高的新人写真偶像`→`…グラビアアイドル`、`S1粉丝感谢祭`→`S1ファン感謝祭`、`性感甜点活动2022`→`セクシー・スイーツ・キャンペーン2022`、`FLASH 2020年现役最强SEXY女优BEST100`→`…女優BEST100`）。

三语一致性修复：5 个空段索引页（`あ/え`、`か/け`、`わ/わ`、`わ/を`、`わ/ん`）的「暂无条目。」在日文、英文版缺失，已补 `該当する条目はありません。` / `No entries.`。英文术语表 5 个括注由中文词改为日文原词。

遗留：数字漂移清单中约 116 条为语体差异（`5月`→`in May`、`过万`→`10,000`、`2019年5月-2020年3月`→`May 2019 – March 2020`、`一百多万`→`one million`），已确认不是丢数据；`check_i18n.py` 未覆盖此类语义比对，仍需人工校对。

## 质量限制

英文内容（2026-09-24 依据中文源重写，未经人工校订）可能存在：

- 人名、作品名、厂商名、机构名和法律名被错误翻译；
- 行业术语、五十音说明或中文音译被错误解释；
- 性别代词、单复数、时态、冠词与语序不自然；
- 中文源中的日文名称被当作待译文本处理；
- 链接文字与目标页面的正式名称不一致；
- YAML front matter 保持中文源值，与页面正文语言不同。

日文内容经过重建后已消除上述机翻错误的主要来源，但仍存在：

- 日语为改写产物，未逐篇人工校订，语序与用词仍可能生硬；
- 中文源自身含混或自相矛盾的表述（日期冲突、表格列数不一致等）按原样保留，未做事实核验；
- 中文源只有中文译名的专有名词按中文原文保留，可能不等于官方标题；
- front matter 的 `tags` 值与文件内出现的链接目标是中文，与正文语言不同。

人物资料、日期、数字、作品信息与来源均以中文源条目为基础。英文内容上线后应视为待人工校订版本；日文内容视为已可读、仍待润色的版本。

## 后续维护流程

新增、删除或修改页面时：

1. 先更新 `docs/zh/` 中的中文源内容。
2. 同步更新 `docs/ja/` 和 `docs/en/` 下相同相对路径的页面；若新增或删除文件，三个版本同时增删。
3. 新增女优条目时，按 `maintenance/zh/五十音排序规则.md` 定位 `{行}/{段}/`，并把链接插入 `docs/{lang}/人物/女优/{行}/{段}/index.md` 与该语言的 `maintenance/{lang}/list.md`、`maintenance/{lang}/list.yaml`（`list.yaml` 三语条数必须一致，否则校验失败）。
4. 新增或删除文件后，确认相应 `index.md` 能到达该页；二级目录页跨分类链接写 `../../`。
5. 改 tag 或经纪公司写法时，按「事务所 tag 命名规范」三语同步，并同步 `经纪公司/{公司}.md` 的成员表。
6. 在 push 前先生成索引和导航，再运行完整校验：

   ```bash
   uv run --locked --no-dev python scripts/content/generate_indexes.py
   ./scripts/build_site.sh
   ```

   若只想快速检查结构与数据，运行：

   ```bash
   uv run --locked --no-dev python scripts/checks/check_i18n.py
   ```

7. 在 push 前执行 pytest、Ruff、依赖审计和 `git diff --check`，完整命令见 [脚本文档](../scripts/README.md)。以上检查全部通过后，检查工作区，只暂存本次修改的文件，提交并 push。失败时先修复并重跑；校验后继续修改时，重跑受影响的检查。快速单项检查用于排查问题，不能代替完整流程。

### 人工校订清单

- 保留人物艺名、厂商和品牌的官方写法；
- 对照来源恢复作品、论文、奖项和法律的正式名称；
- 日文页面的演员名以中文源条目的 `日文名` 字段为准，并与既有页面写法核对一致；
- 检查日文正文中的中文残留词与旧机翻残留；
- 检查英文代词、时态、冠词和单复数；
- 不新增中文源与公开来源未支持的事实，不改动数字、日期与链接目标；
- 不修改文件名与目录结构；
- 校订后再次运行 `./scripts/build_site.sh`。
